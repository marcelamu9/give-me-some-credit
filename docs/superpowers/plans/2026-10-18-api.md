# API de inferencia — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** API FastAPI con `GET /health`, `POST /predict` (probabilidad, banda, nivel, 3 razones SHAP promediadas sobre las 5 copias calibradas) y `GET /model-info`, con los ejemplos de la demo en `/docs` y tests que corren sin el modelo real.

**Architecture:** `schemas.py` define los contratos Pydantic (nombres de Kaggle como alias, validación por rango). `service.py` carga el artefacto y hace la lógica pura: probabilidad, banda y contribuciones por variable promediadas sobre `calibrated_classifiers_`. `main.py` es una capa delgada: fábrica `create_app`, lifespan que carga el modelo una vez, endpoints y 503 si falta. Los tests usan un modelo sintético con la misma estructura de artefacto.

**Tech Stack:** FastAPI, Pydantic v2, Uvicorn, httpx (TestClient), SHAP, scikit-learn, LightGBM, pytest, uv + poe.

**Spec:** `docs/superpowers/specs/2026-10-18-api-design.md`

## Global Constraints

- Artefacto: `cfg.paths.models / "champion.joblib"` = `{"model", "features", "t_low", "t_star"}`; metadata: `cfg.paths.models / "champion_metadata.json"`. `model_version` = `metadata["trained_at"]`.
- Decisión: `assign_band(p, t_low, t_star)` y `RISK_LEVEL` de `credit_risk.decision.policy`; nada de umbrales hardcodeados.
- El preprocesamiento es el del artefacto (el `Pipeline` dentro del modelo calibrado); la API no reimplementa tratamientos.
- JSON con los nombres originales de Kaggle (`FEATURES` de `credit_risk.data.schema`); `extra="forbid"`.
- Rangos: `age` 18–120; conteos 0–98; `NumberOfDependents` 0–20 o `null`; ratios ≥ 0; `MonthlyIncome` ≥ 0 o `null`.
- `probability` redondeada a 4 decimales; `top_reasons` siempre con 3 elementos `{feature, description}`.
- Dependencias nuevas: `fastapi`, `uvicorn`; dev: `httpx`. Ninguna otra.
- Los tests del CI no leen `models/champion.joblib` ni `data/`; los que usan el modelo real se saltan si el artefacto no existe.
- Documentación en español; código e identificadores en inglés. Un commit por tarea. `uv run poe check` en verde antes de cada commit. No hacer `git push`.

## Review Focus

1. Cliente con `MonthlyIncome` y `NumberOfDependents` en `null` → 200 y predicción válida (el pipeline imputa). (Test en Task 3.)
2. Cliente con códigos 96/98 → 200 y, si aparece como razón, `has_special_past_due_code` se muestra como `NumberOfTimes90DaysLate`. (Tests en Tasks 2 y 3.)
3. Valores extremos (`DebtRatio = 1e9`, `RevolvingUtilization… = 5e4`) → 200 y probabilidad en [0, 1] (el pipeline recorta). (Test en Task 3.)
4. `age: 30.5` o el nombre en snake_case en lugar del de Kaggle → 422, no un valor redondeado ni un campo ignorado. (Test en Task 1.)
5. Artefacto ausente o metadata ausente → la app arranca y responde 503, nunca 500. (Test en Task 3.)

### Task 2: Servicio de predicción y razones

**Files:**
- Create: `src/credit_risk/api/service.py`, `tests/api_support.py`, `tests/test_api_service.py`

**Interfaces:**
- Consumes: `ClientFeatures.to_frame()` (Task 1); `assign_band`, `RISK_LEVEL`; `MODEL_FEATURES`; `candidate_specs`, `calibrate` (para el modelo sintético).
- Produces:
  - `@dataclass(frozen=True) LoadedModel(model, features: list[str], t_low: float, t_star: float, metadata: dict)`, con propiedad `version -> str` (`metadata["trained_at"]`).
  - `load_model(model_dir: Path) -> LoadedModel | None` — `None` si falta `champion.joblib` o `champion_metadata.json`.
  - `REASONS: dict[str, tuple[str, str]]` — variable del modelo → (`feature` devuelto, `description`), exactamente la tabla de la spec §4.
  - `feature_contributions(model, row: pd.DataFrame) -> pd.Series` — índice = `MODEL_FEATURES`; promedio sobre `model.calibrated_classifiers_` de: SHAP `TreeExplainer` en el paso `"model"` del pipeline de cada copia sobre `pipeline[:-1].transform(row)` (clase positiva; si SHAP devuelve lista, usar `[1]`; si 3D, `[:, :, 1]`), o `coef_[0] * x` si el estimador final tiene `coef_`. Silenciar avisos de SHAP con `warnings.catch_warnings()`.
  - `top_reasons(contributions: pd.Series, n: int = 3) -> list[dict[str, str]]` — positivas de mayor a menor; si faltan, completar con el resto por valor absoluto descendente; mapear con `REASONS`; deduplicar por `feature` devuelto conservando la primera aparición.
  - `predict(loaded: LoadedModel, row: pd.DataFrame) -> dict` — claves `probability` (round 4), `decision`, `risk_level`, `top_reasons`, `model_version`.
- `tests/api_support.py` (helper de tests, no es test): `build_model_dir(directory: Path, kind: str = "lightgbm", seed: int = 0) -> Path` — 600 filas sintéticas (mismo patrón que `make_partition` de `tests/test_models_train.py`; importarla de ahí), pipeline de `candidate_specs(seed)[kind]` con un modelo pequeño (`set_params` p. ej. `model__n_estimators=30` para árboles), `calibrate(..., cv_folds=5)`, y escribe `champion.joblib` (`t_low = 0.05`, `t_star = 0.20`) y una `champion_metadata.json` mínima con `trained_at`, `champion`, `thresholds`, `costs`, `review_capacity`, `test_metrics` (5 claves) y `features`.

- [ ] **Step 1: Tests que fallan** (fixture `scope="module"` que llama a `build_model_dir(tmp_path_factory...)` para `"lightgbm"` y otra para `"logistic"`):
- `test_load_model_missing_returns_none(tmp_path)`.
- `test_load_model_reads_artifact`: `version == metadata["trained_at"]`, `t_low < t_star`.
- `test_contributions_average_the_five_copies`: `len(model.calibrated_classifiers_) == 5`; calcular en el test el SHAP de cada copia por separado y su media → igual a `feature_contributions` (`np.allclose`).
- `test_contributions_for_logistic`: con el modelo `"logistic"`, devuelve `MODEL_FEATURES` sin NaN.
- `test_top_reasons_positive_first`: `Series` sintética con 4 positivas → 3 mayores positivas en orden.
- `test_top_reasons_fills_with_absolute`: 1 positiva + negativas → 3 razones, la positiva primero.
- `test_top_reasons_maps_and_deduplicates`: `income_unavailable` y `MonthlyIncome` ambas altas → una sola razón `MonthlyIncome` (la de mayor contribución) y se toma la siguiente; `has_special_past_due_code` → `feature == "NumberOfTimes90DaysLate"` y descripción de la spec.
- `test_predict_matches_artifact_probability`: `predict(...)["probability"] == round(model.predict_proba(row)[0, 1], 4)`; `decision == assign_band(...)`; `risk_level == RISK_LEVEL[decision]`; 3 razones.
- `test_predict_single_row_with_special_codes_and_nulls`: fila con 98 en las tres de atraso e ingreso/dependientes `NaN` → probabilidad en [0, 1].
