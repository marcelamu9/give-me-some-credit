# Datos + EDA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Diagnóstico de calidad de `cs-training.csv`, deduplicación exacta, split estratificado test/valid/train y EDA estadístico solo sobre el train interno, con hallazgos documentados.

**Architecture:** Funciones puras y testeadas en `src/credit_risk/data/` (esquema, carga, calidad, split) y `src/credit_risk/eda/` (perfilado y gráficos). Un notebook `notebooks/01-eda.ipynb` solo orquesta esas funciones sobre los datos reales, guarda figuras en `reports/figures/` y particiones en `data/interim/`. Un resumen en `docs/eda_findings.md` recoge las cifras del notebook ejecutado.

**Tech Stack:** Python 3.11, pandas, numpy, scikit-learn (`train_test_split`), matplotlib, pytest, Jupyter (ipykernel + nbconvert), uv + poe.

**Spec:** `docs/superpowers/specs/2026-10-17-datos-eda-design.md`

## Global Constraints

- Solo diagnóstico: la única transformación de datos es eliminar duplicados exactos (se conserva la primera aparición). Nada de imputar, recortar, recodificar ni filtrar.
- Duplicado exacto = filas idénticas en las 11 columnas (10 variables + target), ignorando el ID. Los NaN cuentan como iguales.
- Split en dos pasos, estratificado por el target: 20 % test; del resto, 80 % train / 20 % valid. Semilla `cfg.seed`; proporciones en `cfg.split`.
- Fase 2 recibe **solo** `parts["train"]`. Valid y test no se pasan a ninguna función de EDA.
- `cs-test.csv` no se usa.
- Ningún test lee `data/raw/` ni `data/interim/`: todos usan DataFrames sintéticos.
- Rutas y parámetros siempre desde `credit_risk.config.load_config()`.
- Dependencias nuevas permitidas: `matplotlib` (principal), `ipykernel`, `nbconvert` (dev). Ninguna otra.
- Documentación en español; código, identificadores y commits en inglés (Conventional Commits). Un commit por tarea. `uv run poe check` en verde antes de cada commit. No hacer `git push`.

## Review Focus

1. Variables con muchos empates (las de atraso son ~95 % ceros) → `default_rate_by_decile` no debe fallar con `qcut`; devuelve menos de 10 tramos. (Test en Task 4.)
2. Variables con nulos en el análisis por deciles → los NaN forman un tramo `"missing"` propio, no se descartan en silencio. (Test en Task 4.)
3. Escala logarítmica sobre columnas con ceros (`MonthlyIncome`, ratios) → el gráfico no falla. (Test en Task 5.)
4. Duplicados (exactos y contradictorios) con NaN en las variables → se detectan igual que sin NaN. (Fixture de Task 2.)
5. Ida y vuelta a CSV de las particiones → se conservan el ID como índice `id`, las columnas y los tipos (`NumberOfDependents` sigue float). (Test en Task 3.)
